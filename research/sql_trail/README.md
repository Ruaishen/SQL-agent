# SQL-Trail 复核记录

论文：https://arxiv.org/pdf/2601.17699 （本地 `2601.17699.pdf`，22 页）。
核对日期：2026-09-29。本文区分论文声明、本地实测及尚未验证的解释。

## 结论

之前的 paper_aligned 运行是独立近似实现，不能称为已严格复现论文。
本地已确认交互失效和评分差异，但尚不能充分解释论文 72.8% 与本地 41.39% 的全部差距。
不能从差距推出论文使用 gold 提前停止，也不能承诺统一标签就能达到论文成绩。

## 论文核对

- Table 1：72.8% 对应 Qwen2.5-Coder-3B-Instruct、未微调 Multi-turn Agent、Spider dev、greedy；77.0% 是多数投票。不能把 72.8% 解释为 SFT/RL 后成绩或投票成绩。
- §3.1、A.3、PDF 第 21–22 页：完整 schema、SQL 执行与结果反馈、最终 solution；提示词含一次完整交互示例。
- PDF 第 18 页 Algorithm 1：每轮返回执行反馈和剩余轮数，solution 结束，预算耗尽后生成最终 solution；没有 gold 正确就停止的分支。
- §3.2 明确讨论小模型的格式错误和动作循环，但这只能解释一种风险，不能解释为何论文的同一未微调基座达到 72.8%。

## 实现差异和证据边界

| 项目 | 本地情况 | 判断 |
|---|---|---|
| 数据集 | external_dev 与本地 Spider dev 的 db_id、question、gold SQL 及顺序全部一致，1034 题 | 排除本地错用分割；未比对作者数据库文件哈希 |
| 模型 | manifest/vLLM 日志指向 3B-Instruct，BF16，无量化配置 | 没有加载成 3B 非 Instruct 的迹象 |
| 最初 31.62% 运行 | 强制先 list_tables、inspect_tables，再作答 | 与论文初始提供完整 schema 的条件不同 |
| 后来 41.39% 运行 | manifest 声明提供完整 schema | 不能继续用缺少 schema 解释此成绩 |
| 系统提示词 | 本地 prompt_template 改写了原文、示例和 schema 展示格式 | 已证实非逐字复现；其效果尚无受控消融 |
| 原文标签 | 正式要求 reasoning，示例却用 think | 论文自身存在不一致；本地统一为 reasoning 是实现选择 |
| 停止机制 | 本地 manifest 写 stop_after_sql_tag；论文伪代码还列出 reasoning 结束标签 | 原文与伪代码如何衔接存在歧义，不能机械照抄为正确实现 |
| 反馈 | 本地轨迹保存的是带列名的制表符文本；论文描述 dataframe | 展示方式不同，其影响尚未量化 |
| 倒计时与消息角色 | 旧轨迹未保存完整请求 messages | 不能凭 observation 字段断言实际请求有或没有倒计时 |
| 当前新工具协议 | 五种工具用 tool 内 JSON，包括 submit_sql | 是用户要求的自定义协议，不能称为论文原始协议，尚未评测 |
| 评分 | 本地 ExecutionVerifier 固定列位置；官方 result_eq 可匹配列排列 | 已离线量化部分影响 |

## 离线重放结果

运行：`PYTHONPATH=. python research/sql_trail/audit.py`。
所有原始最终判分均重现，无判分不一致。

| 运行 | 原评分器 | 官方 result_eq 比较函数 |
|---|---:|---:|
| 多轮 paper_aligned_v2 | 428/1034 = 41.39% | 450/1034 = 43.52% |
| 单轮 full_schema | 594/1034 = 57.45% | 621/1034 = 60.06% |

这里只在原始数据库上使用官方比较函数，不是完整 test-suite 评测；不替换 gold 值、不删除 DISTINCT，仍使用本地执行约束。论文未明确给出评分代码版本及这些开关，不能宣称上述重评分已完全对齐论文。
官方函数来源：https://github.com/taoyds/test-suite-sql-eval/blob/master/exec_eval.py 。下载文件及 SHA256 保存在本目录和 audit_summary.json。

多轮诊断：

- 首个 SQL 正确 436 题，最终正确 428 题。首个 SQL 可能是探索，不是严格单轮对照。
- 首错末对 53 题，首对末错或缺提交 61 题。
- 任意中间步骤正确但最终失败 65 题；其中 27 题缺少最终提交。
- 总计 74 题缺少最终 SQL；389 题执行至少十次 SQL，188 题十次 SQL 完全相同。
- 最终有 174 题未知列、38 题未知表；也存在最初选错表、之后把可执行误当成正确的行为。
- 5892 次模型输出都标为 stop，没有 length 截断证据。
- 假设已有轨迹中任意 SQL 正确即可保留，最多 493/1034 = 47.68%；仅靠挽回途中正确答案无法解释到 72.8%。这是既有轨迹的 oracle 诊断，不是新的正式准确率。

案例 spider_dev_00014：首个查询正确，返回空集；模型误认为需要修复，最终把要求的 Location、Name 改成一行 No stadiums found。说明执行反馈并不是语义正确性标签。

## 尚需实验的原因

优先检查首次生成输入和交互消息构造，而不是直接追加训练：完整原始请求、chat template、schema、提示词、停止符、预算和最后提交都应归档。
在相同 scorer 下，对照原文提示词与当前自定义工具提示词；对原文 reasoning/think 不一致应单独注明选择。
另用完全相同的首次 SQL 对照直接提交、仅执行报错修复、允许语义反思修改，才能分离首次生成变化与后续交互的实际收益。
作者的确切推理代码、schema 序列化和评分配置尚未取得；这部分保留为未确定因素，不推断存在 gold 泄漏。
